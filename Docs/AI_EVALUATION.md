# AI 验证

## 协议兼容

四家预设与自定义服务分别使用固定响应验证：普通 JSON、SSE、流式请求返回普通 JSON、格式错误、401、402、429、500、主动取消。连续片段按约 50 ms 合并，结束或中断立即保留最后收到的正文，不以延时模拟打字。

协议测试不会调用真实模型，不产生模型费用，也不能证明音乐推荐质量。真实模型评估尚未执行：需要配置各厂商的有效账户、模型和密钥，在应用内主动运行下面的任务。

## 固定音乐任务

使用同一组已确认可完整播放的收藏和发现候选，记录模型 ID、日期、时长、收藏比例、来源和用户是否保留结果。测试数据应使用专门的测试收藏；不要公开私人歌曲列表或请求正文。

| 任务 | 必须满足 |
| --- | --- |
| 从收藏选 40 分钟夜晚散步音乐 | 只包含候选 ID，显示完整歌曲的实际时长 |
| 收藏中穿插约 20% 新歌 | 不超过新歌比例，标明实际收藏与发现数量 |
| 只听收藏，少些人声 | 不混入未收藏歌曲；缺少音频资料时不虚构乐器或 BPM |
| 保留当前歌曲和两首固定项目，重新安排后面 | 当前项、进度和固定位置保留；过期队列方案拒绝应用 |
| 在上一轮结果上“更熟悉”“换几首” | 多轮上下文生效，排除指定曲目，失败或取消保留原结果与保存状态 |
| 对资料完整和资料缺失的歌曲各写导读 | 事实有实际来源；推断明确，不能生成不存在的引用 |
| 试听一首，再结束试听 | 恢复原队列、原进度和原播放／暂停意图；“播放整组”才替换主队列 |

自动校验覆盖候选范围、可播放性、比例、时长、固定项目、排除 ID 和引用范围。人声、风格、场景匹配和导读质量仍需要实际模型与人工聆听评估。

## 模型清单核对

2026-09-09 核对官方文档，保留现有预设，不替换用户已保存的手动 ID：

- DeepSeek：`deepseek-v4-flash`、`deepseek-v4-pro`。[官方接口说明](https://api-docs.deepseek.com/)
- 百炼：`qwen3.7-plus`、`qwen-plus`；地域与业务空间仍单独配置。[官方模型说明](https://help.aliyun.com/zh/model-studio/qwen3-7-plus)
- Kimi：`kimi-k3`，Chat Completions 地址为 Moonshot API。[官方对话接口](https://platform.kimi.com/docs/api/chat)
- 智谱：`glm-4.7-flash`、`glm-5.2`。[Flash 文档](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.7-flash)、[对话接口](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)

模型可用性还取决于账户权限。连接测试通过只表示这一次短请求成功，不代表额度、稳定性或质量已经长期验证。
